# WAHA gateway — production deployment (OrbStack)

Self-hosted **WAHA** (`devlikeapro/waha`) gateway for Oriole's *Bring Your Own
WhatsApp* integration. Runs anywhere Docker runs — this guide is written for
**OrbStack** on macOS, but every command is standard `docker compose`.

```
deploy/waha/
├── docker-compose.yml   # production config (version-pinned, secrets required)
├── .env.example         # all configurable knobs
├── .env                 # YOUR secrets (generated by init-env.sh, gitignored)
├── scripts/
│   ├── init-env.sh      # generate .env with fresh random secrets
│   └── backup.sh        # tar session+media data → backups/
├── data/                # runtime data (gitignored): sessions + media
└── backups/             # created by backup.sh (gitignored)
```

---

## ⚠️ Read this first — risk & safety

Unofficial WhatsApp **violates Meta's Terms of Service**. Numbers linked
through WAHA can be **banned**. Before running:

- Pair **only a number you are willing to lose** — never a customer's number
  or your main business line.
- WhatsApp **shadow-restricts accounts that message many new contacts**
  ("reachout timelock"). While restricted, sends to *new* chats fail with
  error **463** until the lock lifts. The session stays `WORKING` — **do not
  restart or re-pair**, it lifts automatically (Oriole surfaces this as
  "Restricted" and pauses new-contact sends).
- There is **no 24h window and no template approval** — free-form text works
  anytime. That convenience is exactly what drives bans. Oriole keeps
  reminders/form-sends limited to opted-in customers and enforces daily caps.
- Oriole provides **no deliverability guarantee** — messages can be silently
  dropped or delayed.

## Prerequisites

- **OrbStack** running (`orb` CLI or the menu bar app). Docker Desktop works
  identically.
- Port **3002** free on the host (the WAHA API — configurable via `WAHA_PORT`
  in `.env`; defaults to 3002 so it never collides with the Oriole API dev
  server on 3000).
- A phone with WhatsApp for pairing.

## Quick start

```bash
cd deploy/waha

# 1. Generate .env with fresh random secrets (prints your API key)
./scripts/init-env.sh

# 2. Start the gateway
docker compose up -d

# 3. Wait for it to become healthy (OrbStack shows the health in its UI too)
docker compose ps                 # STATUS should read "healthy"
curl -s http://localhost:3002/health   # liveness — answers 200 (keyless; excluded path)

# 4. Dashboard (manage sessions, view QR, create scoped keys)
open http://localhost:3002/dashboard
```

### Connect it in Oriole

1. Oriole → **Integrations** → WhatsApp card → **Bring your own number**
   (unofficial).
2. Accept the consent screen — tick **all four** risk-checkbox statements.
   (No typed phrase anymore; the button stays disabled until every box is checked.)
3. **Gateway credentials — server-managed only:** the Oriole API server must
   be configured with `WAHA_GATEWAY_URL` + `WAHA_GATEWAY_API_KEY` (root
   `.env`); the dialog never asks the user for gateway credentials — they
   just tick the risk boxes and click **Connect my number**. (The plain key
   printed by `init-env.sh` — stored as `WAHA_API_KEY_PLAIN` in
   `deploy/waha/.env` — goes into the API server's `.env` as
   `WAHA_GATEWAY_API_KEY`; the container env only holds the sha512 *hash*, so
   never paste the hash into Oriole.)
4. Oriole creates the session and shows the **QR** — scan it with the phone
   (WhatsApp → Linked devices → Link a device), or use the **pairing code**
   ("Link with phone number instead").
5. The card flips to **Connected**; your number appears. Done.

### Webhook reachability (local dev)

Oriole points WAHA's webhooks at
`{API_URL}/api/webhooks/waha/{workspaceId}`. For local development the API
runs on your Mac, so the API must be reachable **from inside the container**:

- Run the API with `API_URL=http://host.docker.internal:3001` (OrbStack
  resolves `host.docker.internal` to your Mac automatically — the compose
  file also adds it for Linux compatibility).
- Confirm with `docker compose logs waha` after sending yourself a message:
  webhook deliveries are logged (HTTP level).

## Full stack in one command (local development)

A compose **dev overlay** (`docker-compose.dev.yml`) adds the **Oriole API**
(`tsx watch`, hot-reload) and the **Inngest Dev Server** next to the gateway
— so local development needs **no separate `pnpm dev:inngest` terminal** and
no host-run API. Everything runs in containers:

```bash
cd deploy/waha
# Stop host services on the same ports first: the API (pnpm dev) on 3000 and
# any host `inngest dev` on 8288 — they'd collide with the published ports.
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

| Service | URL | Notes |
|---|---|---|
| WAHA gateway | http://localhost:3002 | unchanged from the base compose |
| Oriole API | http://localhost:3000 | dev mode, hot-reloads on every save (repo bind-mounted) |
| Inngest Dev Server | http://localhost:8288 | UI shows functions + runs; replaces `pnpm dev:inngest` |

### Requirements (one-time)

1. **`deploy/waha/.env`** — gateway secrets (`./scripts/init-env.sh`).
2. **Root `.env`** (`../../.env`) — API secrets: `DATABASE_URL`, `NEON_AUTH_URL`,
   `PADDLE_*`, `RESEND_API_KEY`, `VAPI_API_KEY`, `TELNYX_API_KEY` (BYO Telnyx), …
3. **Container-network URLs in root `.env`.** The API reads root `.env` and
   those values override compose (`loadRootEnv`), so for full-stack mode set:

   ```env
   API_URL=http://api:3000
   WAHA_GATEWAY_URL=http://waha:3000
   WAHA_GATEWAY_API_KEY=<the plain key from deploy/waha/.env>
   ```

   - `API_URL` is what the gateway posts webhooks to (`http://api:3000/...`).
   - `WAHA_GATEWAY_URL` + key = **managed mode**: the BYO dialog hides the
     gateway fields entirely. Switch these back to host values
     (`http://host.docker.internal:3000` / `http://localhost:3002`) if you
     run the API on your Mac again.

### What you get

- **One command** starts gateway + API + Inngest; `docker compose down` stops them.
- **Hot reload**: edit any file in the repo → `tsx watch` in the container
  restarts the API.
- **Inngest pipeline works**: the Dev Server syncs the API's functions
  ("apps synced" in `docker compose logs inngest`), and the SDK sends events
  to `http://inngest:8288` (via `INNGEST_DEV`).
- **IPv6 pitfall handled**: OrbStack containers have no IPv6 route but DNS
  still returns AAAA records for some hosts (Neon pooler) → hostname
  connections hang. The API service disables IPv6 (`net.ipv6.conf.*.disable_ipv6`)
  so `DATABASE_URL` always connects.

### Updating dependencies

node_modules live in named volumes seeded from the image (Linux binaries —
never the macOS host's). After changing `package.json` / the lockfile, rebuild
and refresh the volumes:

```bash
cd deploy/waha
docker compose -f docker-compose.yml -f docker-compose.dev.yml down -v
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

### Verifying

```bash
curl -s http://localhost:3000/api/health            # API up
curl -s http://localhost:3000/api/health/ready      # DB reachable
curl -s http://localhost:8288                       # Inngest UI
cd deploy/waha && docker compose -f docker-compose.yml -f docker-compose.dev.yml logs -f inngest
# send yourself a WhatsApp message → watch the function run + reply in the inbox
```

> **Existing channels**: a channel connected while the API ran on your Mac
> stores host URLs (`providerConfig.baseUrl`, and the gateway session's
> webhook URL). Re-run the channel setup (Integrations → WhatsApp → BYO) or
> update those two values to `http://waha:3000` / `http://api:3000/...` for
> container mode.

## Making the gateway reachable (production)

The Oriole **API server** must reach this gateway for every send/probe, and
the gateway must reach the API's webhook endpoint. The compose binds
`127.0.0.1` by default — pick one of these when the API isn't on the same host:

| Option | When | How |
|---|---|---|
| **OrbStack tunnel** | quick public URL from your Mac | `orb tunnel http://localhost:3002` → use the `https://…` URL as Gateway URL; set `WAHA_BIND_ADDR` stays `127.0.0.1` |
| **Cloudflare Tunnel** | permanent hostname, no open ports | `cloudflared tunnel --url http://localhost:3002` (or a named tunnel + ingress) → use the `https://…` URL |
| **Reverse proxy + TLS** | gateway on a VPS/server | set `WAHA_BIND_ADDR=0.0.0.0`, put Caddy/Nginx/`cloudflared` in front with HTTPS, and allow-list the Oriole API egress if possible |

**Always put HTTPS in front of the gateway** — it carries an admin API key
and the dashboard password. Never publish `WAHA_BIND_ADDR=0.0.0.0` on a raw
public port.

## Sessions, pairing & the timelock

- Sessions are **named `ws_<workspaceId>`** by Oriole and **survive restarts**
  (`data/sessions` volume). Re-pairing is only needed after a logout or a
  data loss.
- The **QR rotates** while `SCAN_QR_CODE` — Oriole refetches it automatically
  and shows a countdown. If it expires, hit **Refresh QR**.
- **Pairing code vs QR:** Oriole offers both. If you set a custom
  `WAHA_CLIENT_DEVICE_NAME`, the pairing-code flow stops working — keep the
  default device name (the compose leaves it unset).
- **Error 463 (reachout timelock):** the session stays `WORKING`; the lock
  lifts on its own. Oriole shows "Restricted" and blocks sends to new
  contacts until it passes. **Do not restart or re-pair to "fix" it** — that
  makes it worse.
- **Banned:** repeated 463 beyond the lock, 402/403, or bodies mentioning
  banned/blocked → Oriole marks the number **Banned**, auto-pauses outbound,
  and the dashboard chip turns red. Only a new number (fresh session) recovers.

## Backups & restore

Sessions live in `data/sessions` — losing them means **re-pairing with the
phone**. Media files are persisted too (`WHATSAPP_FILES_LIFETIME=0` disables
expiry, so `data/media` grows over time — the backup tar covers both).
Back them up regularly:

```bash
cd deploy/waha
./scripts/backup.sh          # → backups/waha-<timestamp>.tar.gz (keeps last 7)
```

Schedule it (macOS/launchd or OrbStack task) and copy `backups/` off-machine.
Restore:

```bash
cd deploy/waha
docker compose down
rm -rf data/sessions data/media      # replace, don't merge
tar -xzf backups/waha-<timestamp>.tar.gz
docker compose up -d                 # sessions resume; re-verify with `docker compose ps`
```

## Updating WAHA

```bash
cd deploy/waha
docker compose pull          # fetch the pinned (or newly pinned) image
docker compose up -d         # rolling restart; sessions persist in data/
```

Pin `WAHA_IMAGE_TAG` in `.env` to a release you've tested. After an upgrade,
send yourself a message to confirm webhooks still arrive. **Never run `:dev`
long-term.**

## Logs & troubleshooting

```bash
docker compose logs -f waha        # JSON lines: requests, webhook deliveries, session events
curl -s http://localhost:3002/health                  # liveness (no auth, excluded path)
curl -s -H "X-Api-Key: $WAHA_API_KEY_PLAIN" http://localhost:3002/api/sessions?all=true
```

| Symptom | Likely cause | Fix |
|---|---|---|
| `docker compose ps` shows unhealthy | image still pulling, or health path differs on this version | wait; check logs; healthcheck tries `/api/health` then `/health` |
| Setup says "URL tersebut bukan gateway WAHA" | wrong URL/port, or key wrong | use `http://localhost:3002`; verify with the sessions curl above |
| Sends fail with **463** | reachout timelock | don't restart; Oriole auto-blocks new contacts until it lifts |
| Sends fail with 402/403 / "banned" | number flagged | re-pair a different number; Oriole auto-pauses outbound |
| No webhooks in Oriole inbox | `API_URL` not reachable from container | run API with `API_URL=http://host.docker.internal:<port>`; check logs |
| Session lost after restart | `data/sessions` not mounted or wiped | mount `./data/sessions:/app/.sessions` (compose does); restore from backup |
| "QR expired" loop | gateway session crashed mid-pair | `docker compose restart`, refresh QR in Oriole |
| Full-stack: no webhooks in inbox | `API_URL` still host-oriented in root `.env` | set `API_URL=http://api:3000` (and `WAHA_GATEWAY_URL=http://waha:3000`) — see "Full stack in one command" |
| Full-stack: sends fail `ECONNREFUSED localhost:3002` | stored `providerConfig.baseUrl` points at the host port | re-run channel setup or update baseUrl to `http://waha:3000` |
| Session stuck `FAILED` but number still paired | WhatsApp NOWEB engine connection failure (not the compose stack) | wait; restart session once; re-pair (scan QR) if it persists |

## Security hardening checklist

- [ ] `.env` has **fresh random** `WAHA_API_KEY` + dashboard password (run
  `init-env.sh`, never reuse the example values).
- [ ] Gateway bound to `127.0.0.1` or behind **HTTPS** (tunnel/reverse proxy).
- [ ] `WAHA_DEBUG_MODE=false`, `WAHA_DEV_ENABLED=false` (compose defaults).
- [ ] No custom device name unless you never use the pairing-code flow.
- [ ] `data/` is backed up and `backups/` copied off-machine.
- [ ] The **same** gateway key is shared with Oriole — it's an admin key
  (session create, QR, send). For tighter control, create a **session-scoped
  key** in the dashboard (`POST /api/keys`) restricted to that session with
  read/send/control, and use it as the Oriole key (see
  `spikes/waha/README.md` → "Keys / security").
- [ ] Monitor the Oriole dashboard chip: red = banned, orange = restricted,
  red "Disconnected" = gateway unreachable.

## Reference — env vars

| Variable | Default | Notes |
|---|---|---|
| `WAHA_IMAGE_TAG` | `noweb-arm-2026.7.2` | engine+arch split; `noweb-…` on x86; `:dev` only for experiments |
| `WAHA_API_KEY` | **required** | sha512 hash — the container never sees the plain key |
| `WAHA_API_KEY_PLAIN` | **required** | the actual key you paste into Oriole |
| `WHATSAPP_SWAGGER_USERNAME` / `WHATSAPP_SWAGGER_PASSWORD` | required | Swagger login (same origin as API) |
| `WAHA_DASHBOARD_USERNAME` / `WAHA_DASHBOARD_PASSWORD` | required | dashboard login |
| `WAHA_BIND_ADDR` | `127.0.0.1` | set `0.0.0.0` only behind TLS |
| `WAHA_PORT` | `3002` | host port; Oriole Gateway URL = `http://localhost:<WAHA_PORT>` |
| `WHATSAPP_DEFAULT_ENGINE` | `NOWEB` | browserless; matches Oriole |
| `WAHA_NAMESPACE` | `all` | share API keys across engines |
| `WAHA_PRINT_QR` | `false` | Oriole fetches QR via API |
| `WHATSAPP_FILES_FOLDER` / `WHATSAPP_FILES_LIFETIME` | `/app/.media` / `0` | persist media |
| `WAHA_LOG_FORMAT` / `WAHA_LOG_LEVEL` | `JSON` / `info` | production log pipeline |
| `TZ` | `Asia/Jakarta` | container timezone |
| `ORIOLE_API_PORT` | `3000` | dev overlay: host port for the API (Vite proxies `/api` → this) |
| `INNGEST_PORT` | `8288` | dev overlay: host port for the Inngest Dev Server UI |
| `INNGEST_IMAGE_TAG` | `latest` | dev overlay: Inngest image tag (pin a tested release) |

Full variable reference: https://waha.devlike.pro/docs/how-to/config/
